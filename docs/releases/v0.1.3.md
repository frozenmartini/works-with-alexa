# v0.1.3

**Lock and unlock now work, and every device write has been verified on a real
device.** No configuration changes and nothing to do after updating.

- **Locks lock and unlock.** Both commands were rejected by Amazon with
  `BAD_REQUEST`, so a lock could be read but never driven. The request no
  longer carries an empty payload, which Amazon refused for locks. Verified on
  a Lockly smart lock: both commands accepted, and the reported state followed.
- **Thermostat writes verified.** Mode and the lower and upper setpoints were
  verified on an ecobee and confirmed by the next poll. In AUTO, a
  target-setpoint write moves both the lower and upper setpoints on the device.
  Alexa does not report the target back in that mode, so the Target Setpoint
  entity returns to what Alexa reports after its 30-second hold.
- **One thermostat-mode request.** Mode changes send the single request shape
  that was verified. The second, guessed shape that was tried after a
  rejection is gone, so a rejected mode change fails at once instead of being
  retried in a different form.

The README's *What is verified* table is updated to match.

Requires Home Assistant **2026.3.0 or newer**, unchanged. No new Python
requirements.
